# Optional companion handoffs

CPO → BI and CPO → Microgroup are one-way handoffs. Companions return evidence/artifacts, never call CPO or each other. Reuse one result for one bounded question; repeat only for new material evidence, not to satisfy an arbitrary count.

BIRequest: decision question, actual source IDs, available rows/series, definitions, units/currency/scale, entity/scope, period, accounting basis, plan/actual version, comparison or scenario rule, output format and known gaps. Return actual chart files or explicitly labelled specification, exact input/provenance, checks, limitations and changed decision surfaces. Chart colors alone are not business evaluation.

MicrogroupContextRequest: decision, provisional behavioral group, geography, freshness, decision surfaces, current evidence, access/privacy boundary, practical evidence budget and stop condition. Return MicrogroupContextPack using the companion's structured output contract: observations, source ledger, interpretations, hypotheses, contradictions, confidence, limits, freshness and changes/no changes to the decision. Convenience observations are not population statistics.

Use neither companion for a narrow pricing formula, ordinary metric definition, routine JTBD wording or unrelated code question. Use BI alone for a supplied-data chart. Use Microgroup alone for a local research question. Use both only when numeric business comparisons and contextual audience evidence independently change the same strategic choice.

If a companion is not installed or tools cannot execute, provide the relevant bounded evidence/calculator/chart contract independently, disclose the unavailable execution and proceed as far as supported evidence permits. Never claim automatic invocation merely because a skill name appears in metadata. Standard skill discovery and invocation behavior depend on the host runtime.
