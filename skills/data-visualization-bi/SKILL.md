# Data Visualization & BI

Переноси из референса способ читать и исследовать данные. Сохраняй задачу пользователя, формат результата и дизайн его продукта. Галерея — источник решений, а не обязательный макет для каждого графика.

## Преемственность

Новый источник расширяет библиотеку, а не сбрасывает согласованный дизайн. Сначала найди предоставленные пользователем картинки и принятые решения в материалах текущего проекта; не проси повторно прислать доступные файлы. Приоритет: актуальный запрос → согласованные требования проекта → конкретный пользовательский образец → дополнительные галереи. Исторический макет не отменяет более позднее решение.

Для финансовых графиков, ПланФакта/Сводно или расширения существующей библиотеки прочитай [пользовательские финансовые референсы](references/planfact-patterns.md). Они дополняют общую библиотеку. Не переноси клиентские цифры, брендинг или финансовые формулы в переиспользуемый скилл.

## Где применять

- Для дашборда или графика по BI-референсу прочитай [библиотеку приёмов](references/bi-patterns.md). Выбери один близкий сценарий; не загружай все внешние галереи при каждом запуске.
- Для выбора редких/сложных форм и проверки графического дизайна прочитай [каталог визуальных форм и правила читабельности](references/chart-design.md). Используй сложную форму только если она делает сравнение, структуру или неопределённость понятнее.
- Для BCG, ADL, оценочных матриц, radar/многокритериальных профилей и MCDA прочитай [методы принятия решений](references/decision-methods.md). Сначала установи решение и входные данные; наличие метода в библиотеке не означает поддержку его отрисовки выбранным инструментом.
- Для визуализации **в разговоре** используй доступный инструмент визуализации и его актуальный контракт; если его нет, создай локальный SVG по контракту ниже. В обычных графиках не добавляй карточки и фильтры без запроса; в явно запрошенном макете дашборда применяй режим UI mockup.
- Для страницы существующего приложения работай в его проекте и дизайн-системе. Для самостоятельного сайта используй соответствующий workflow сайта; для Excel/Sheets или экспортируемого научного графика — инструменты целевого формата. BI-референс не меняет выбранный пользователем продукт на DataLens.
- Для простого графика без BI-референса достаточно профильного инструмента. Не превращай его в дашборд.

## Как переносить референс

1. Определи читателя, решение, период, детализацию исходных строк и доступные показатели. Для макета с отсутствующими данными используй явно помеченные демонстрационные значения или пустые состояния. Для анализа не выдумывай данные, планы, бенчмарки и выводы.
2. Подбери из библиотеки близкий референс по задаче и форме данных. Если пользователь дал конкретный образец, изучи его страницу и видимый скриншот; подпись карточки не подтверждает внутреннее устройство или работу фильтров. При недоступности отметь ограничение и используй проверенный пример, не приписывая ему свойства закрытой страницы.
3. Зафиксируй коротко, внутри рабочего контекста: **источник → наблюдение → что переносим → что меняем → чего не проверили**. Для простого задания не выпускай отдельный отчёт об этом. Сохраняй ссылку в выдаваемом дизайн-брифе, если бриф запрошен.
4. Выбери композицию и типы графиков по вопросу, а не по красоте миниатюры. Различай обзор, объяснение отклонений и детали. Не копируй число карточек, логотип, палитру или случайный набор метрик.
5. Реализуй только полезные для задания действия. Если есть общий фильтр, все зависящие показатели и графики должны обновляться согласованно; покажи область его действия, активное значение и способ сброса. Даже в краткой спецификации фильтра укажи состояние без строк: «нет данных за выбранный период», со сбросом, без подмены отсутствующих наблюдений нулями. Отличай фильтрацию от перехода к деталям и сценарного расчёта.

## Проверка результата

- У показателя понятны единица, период и база сравнения; у доли — знаменатель. При нулевой базе процентного изменения показывай «нет базы», не бесконечность. Не усредняй проценты разных групп без весов.
- Полосы сравнения начинаются с нуля; отклонения используют знаковую ось. Для линий допустим обоснованный ненулевой диапазон с явно видимыми делениями. Общие шкалы — для сравнимых величин, отдельные — для разных единиц. Не интерполируй пропущенные даты как наблюдавшиеся значения.
- Цвет имеет постоянный смысл. Знак изменения и оценка результата — разные вещи: без заданной цели, норматива или правила благоприятности изменение показывается нейтрально. Например, рост затрат 100 → 120 означает +20%, но сам по себе не доказывает ухудшение: мог вырасти объём деятельности. Не назначай ему автоматически ни зелёный, ни красный статус. Оценочный статус, когда он обоснован, продублирован текстом, знаком или формой.
- Сверь новый путь генерации с уже принятыми композициями: поддерживаемые ряды не должны исчезать за новым шаблоном или исключающим переключателем. Для составного P&L проверь, что выручка, затраты и точная стадия прибыли показаны вместе, когда их сопоставимость подтверждена.
- Итог, графики и детализация согласованы после фильтра. Пустая выборка отличается от нуля и ошибки. Нужные значения доступны без наведения.
- На узком экране блоки перестраиваются по важности, подписи остаются читаемыми; график не уменьшается целиком до нечитаемого состояния. Выполни проверки выбранного инструмента вывода. Не называй статический скриншот проверкой интерактивности.
- Для нетривиального запроса проверь, не теряет ли пользователь важное сравнение из-за одного привычного графика: выбери форму из подходящего семейства в [каталоге графиков](references/chart-design.md), но сохрани понятную подпись, легенду и краткое объяснение чтения.

Для повторной проверки инструкций есть [сценарии](evals/cases/). Они оценивают решения и границы применения, а не совпадение формулировок.

## Independent execution

Read [renderer-contract.md](references/renderer-contract.md) and use `python3 scripts/render_chart.py input.json output.svg` for a reproducible local line or grouped bar chart. The renderer uses only Python's standard library, creates an actual SVG with exact values, and never supplies missing data. It is a minimal chart renderer, not a full interactive dashboard engine. For richer forms use an available appropriate tool and verify its actual capabilities; otherwise return a clearly labelled specification with the unsupported feature disclosed.

No private dashboard service or external plugin is required. Installed skills do not establish connected-service access. Preserve the requested output format: static SVG is not an interactive dashboard, Excel workbook or presentation. Do not claim interaction was tested from a screenshot. Existing reference guidance remains applicable to independently chosen tools.

When called by CPO, return chart files, the data/provenance contract, interpretation limits, missing inputs and verification. Do not invoke CPO or Microgroup; CPO handles integration. When used independently, answer the user's chart question directly without coordinating other skills.
